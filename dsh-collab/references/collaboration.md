# 紧凑协作约定

首次派单或编写结果时读取。本页是消息正文约定，不新增 CLI 参数、控制标记或 task schema。全局任务分级与风险验收规则仍适用。

## 派单模板

只填写本任务特有信息；常规 Standard 通常一次派单，不要求额外交接文件。已存在的计划或证据使用执行端可访问的路径引用。

```text
GOAL: <最终任务目标>
WORKSPACE: <项目绝对路径>
BOUNDARY: <用户明确约束及必要权限、安全、兼容边界>
ACCEPTANCE:
- A1: <可核查的完成条件>
- A2: <其他必要条件；按需增减，不凑数>
CONTEXT: <DSH 无法自行取得的必要背景，或相关证据位置；无则省略>
```

验收条件由 Codex 派单前定义，来自用户目标；描述结果，不指定方案。DSH 自主规划、实施、选择测试并修复，不必在每次派单重复自主权限、内部步骤、子 agent 数量、轮次预算或普通进度节点。用户已有预算与既有桥接故障/超时保护仍生效，不新增内部配额。复杂项目仅按真实依赖和风险补关键里程碑；涉及部署时明确授权边界。

首轮 bridge brief 已提供通用职责、安全及控制标记。需要结果格式时引用执行端可读取的本文件路径，无法读取才附必要模板；不复制全局规则或历史。首次投递失败且 brief 未确认送达时，按 [命令参考](commands.md#轮次交接与恢复) 补齐关键契约。

## 结果模板

沿用桥接识别的独立行标记。交付可评审时使用：

```text
DSH_RESULT: <实际完成摘要，部分完成如实说明>
REVIEW_READY: <供 Codex 核查的交付物>
CHANGED: <文件绝对路径 + 一句话差异>
TESTS: <精确命令、退出码、PASS/FAIL；未跑项与原因>
ACCEPTANCE: <逐项 A1/A2… 的满足情况与 TESTS/EVIDENCE 对应；未满足或未验证项如实注明>
RISKS / DISSENT: <真实问题、假设、未验证边界或替代方案；无则 None>
EVIDENCE: <diff、日志、产物绝对路径>
NEXT: <需要 Codex 决策的事项；无则 None>
```

真实阻塞时增加独立行 `QUESTION: <具体待决事项>`，未就绪不写 REVIEW_READY；没有阻塞时省略整个 QUESTION 行，不能写 `QUESTION: None/无`。普通建议写正文。不要用 `STATUS: REVIEW_READY | BLOCKED | FAILED` 替代控制标记；执行状态和 transport 失败由桥接记录，自报不能改写 task.json 或批准自己。

详细过程留在现有日志。Codex 按风险独立核查，可靠证据可复用，自报不能替代验收；返工仅给未满足条件、客观证据和必要边界，DSH 自定修复方式。续接不复述背景，不要求长篇自评或逐文件审批。

## 效率证据（需要比较时）

复用已有任务/事件/评审记录，记录可取得的数据：等级与路由原因、Codex-only / DSH synchronous / DSH asynchronous、实际模型、轮次、工具调用、执行与端到端耗时、独立发现问题数、返工轮次及最终验收结果。不为普通任务强制生成统计报告，不建数据库、服务或新状态字段。

Codex 输入/缓存输入/未缓存输入/输出 token 与 DSH 用量只引用运行环境真实提供的值，缺失写 unknown；缓存输入不等于同价计费输入，不推算官方额度百分比。跨多个实际任务比较，区分等待时间与模型执行时间；规则优化的预期收益不能写成已实现的费用节省。
